# Стратерия хостинга для SFMShop

## Оценка нагрузки

Текущую нагрузку проекта можно оценить как небольшую - до 100 RPS.

Ожидаемая нагрузка после роста количества пользователей примерно
100 - 500 RPS.

Пиковая нагрузка может достигать 800 RPS, например во время акций
или резкого роста количества пользователей.

## Выбор хостинга

Для SFMShop можно рассмотреть Cloud хостинг, например Google Cloud.

Такой вариант подходит, потому что ожидаемая нагрузка проекта
находится в диапазоне 100 - 500 RPS, а пиковая до 800.

Cloud позволит:
- увеличивать ресурсы при росте нагрузки.
- запускать несколько экземпляров приложения.
- использовать балансировщик нагрузки.
- подключать автоматическое масштабирование.
- использовать управляемые сервисы для БД и кэша.

Для текущей нагрузки до 100 RPS можно было бы использовать VPS
или PaaS, но Cloud оставляет больший запас на рост проекта.

## Стратегия масштабирования

На начальном этапе проект может работать на небольшом Cloud.

При росте нагрузки будет использоваться горизонтальное масштабирование.
Запуск нескольких экземпляров приложений, а нагрузка распределяется через
load balancer.

Если нагрузка продолжит расти, можно использовать k8s для управления
несколькими экземплярами приложения и авто-масштабирования.

Перед увеличением количества серверов необходимо также оптимизировать
само приложение:

- использовать Redis кэши
- оптимизировать SQL запросы и индексы
- избегать N+1
- использовать асинхронный I/O
- выносить долгие задачи в брокер
- уменьшить количество обращений к внешним API

## Мониторинг

Для принятия решения о масштабировании необходимо отслеживать:

- RPS
- latency
- CPU
- RAM
- нагрузку на Postgre и Redis

## Запас на рост

Выбранная cloud-инфраструктура рассчитана не только на текущую нагрузку,
но и ожидаемый рот до 800 RPS.

При дальнейшем росте инфраструктуру можно расширить с помощью k8s,
горизонтального масштабирования и дополнительных балансировщиков.
