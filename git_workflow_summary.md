# Git Workflow для проекта SFMShop

## Использованные команды Git
- `git init` - инициализация локального Git-репозитория
- `git add` - добавление файлов в staging area перед коммитом
- `git commit -m` - создание коммита с сообщением
- `git log --oneline` - краткий просмотр истории коммитов
- `git log --oneline --graph --all` - просмотр истории с графом веток
- `git log --stat` - просмотр статистики изменений по файлам
- `git branch` - просмотр локальных веток
- `git branch -a` - просмотр всех веток, включая удалённые
- `git checkout -b` - создание новой ветки и переключение на неё
- `git checkout` - переключение между ветками
- `git merge` - слияние изменений из одной ветки в другую
- `git push -u origin` - отправка ветки в удалённый репозиторий и установка связи с upstream
- `git diff` - сравнение изменений между ветками или состояниями
- `git show` - просмотр содержимого конкретного коммита
- `git cherry-pick` - перенос отдельного коммита в другую ветку
- `git restore` - восстановление изменений в файлах
- `git reset` - откат указателя HEAD и состояния коммитов
- `git remote -v` - просмотр настроенных удалённых репозиториев

## Созданные ветки
- `main` - основная ветка проекта
- `feature/add-discount-system` - ветка для добавления метода `apply_discount()` в класс `Product`
- `feature/add-email-validation` - ветка для улучшения валидации email в классе `User`
- `feature/add-inventory-management` - ветка для добавления методов `check_stock()` и `update_stock()` в класс `Product`
- `feature/add-inventory-management-clean` - чистая ветка для корректного PR по задаче inventory management
- `feature/add-shipping` - ветка для добавления метода `calculate_shipping()` и практики merge conflict

## Разрешенные конфликты
- Конфликт в `src/models/product.py` возник при переносе изменений через `git cherry-pick` в чистую ветку для inventory management.
  Конфликт был разрешён вручную: удалены конфликтные метки, оставлена итоговая версия кода, после чего файл был добавлен в индекс.
- Конфликт в `src/models/product.py` возник при `git merge main` в ветке `feature/add-shipping`.
  В итоговой версии были сохранены оба метода: `calculate_shipping()` и `get_category()`.
  После разрешения конфликта файл был добавлен в индекс и создан merge commit.

## Workflow проекта SFMShop
1. Работа начинается из основной ветки `main`
2. Для каждой новой задачи создаётся отдельная feature-ветка
3. Изменения вносятся в файлы проекта
4. Изменения добавляются через `git add`
5. Создаётся коммит с осмысленным сообщением
6. Ветка отправляется в удалённый репозиторий через `git push -u origin <branch_name>`
7. На GitHub создаётся Pull Request в ветку `main`
8. При необходимости ветка обновляется из `main`
9. Если возникает конфликт, он разрешается вручную
10. После проверки изменения могут быть влиты в основную ветку

## Стратегия работы с ветками для команды
- основная стабильная ветка проекта - `main`
- каждая новая задача выполняется в отдельной ветке формата `feature/<task-name>`
- новая feature-ветка должна создаваться только от `main`
- не рекомендуется создавать новую feature-ветку от другой feature-ветки, так как это приводит к смешиванию истории
- перед созданием новой ветки желательно переключиться на `main` и обновить её
- все изменения отправляются в удалённый репозиторий через отдельные ветки
- слияние изменений выполняется через Pull Request после проверки
- конфликты должны разрешаться вручную с сохранением корректной итоговой версии кода
